Ukrainian scans, invoices, Word and Excel to Markdown - 5 Apify Actors on 7 files, only one got every table right

Five document-to-Markdown Actors from the Apify Store on the same seven Ukrainian files - text PDF, clean and noisy scans, DOCX, XLSX and scanned invoices without table lines. Empty scans, changed prices, lost tables - and the one Actor that got every file right at the lowest price per scanned page.

Search the Apify Store for "PDF to Markdown" and you get dozens of Actors with almost the same promise: text, tables, OCR, ready for RAG. None of them tells you what happens with a Ukrainian scan, an Excel file or a scanned invoice whose table has no lines. So I ran five of them on the same seven files and compared every output with the text the files were made from. All results below are from real runs on 15 November 2026.

Disclosure: one of the five is mine, Document to Markdown for AI. Every number below comes from a real run, the test files are public and the raw outputs are kept, so you can repeat and check all of it.

"Right" means the text, the heading and the table with the correct rows and with every number exactly as in the document.

The seven files

All Ukrainian, all generated from known text, so every character can be checked:

File What it is
text-uk.pdf PDF with a text layer: heading, two sentences, a 3 x 3 table with prices like 96,50
scan-uk.pdf the same page as a clean scan
scan-noisy-uk.pdf the same scan with noise and a slight tilt
doc-uk.docx Word document with the text, a list and the table
sheet-uk.xlsx Excel workbook: the table with a Total row 1,234.50, and a sheet with the sentences
scan-borderless-uk.pdf a scanned invoice: 5 x 6 table without any lines, amounts like 40 530,00 and 2 500
scan-noisy-borderless-uk.pdf the same invoice, noisy and tilted

The last two are the hard case and the most common one: most invoices, waybills and bank statements are printed without table lines. The files are public: https://api.apify.com/v2/key-value-stores/FloomuI2DrQCJazY8/records/<file name>.

The Actors are the most used ones for this search plus one that lists Office formats. Settings: Ukrainian OCR wherever the Actor has a language option (ukr); nidamindllc has no language option.

What stood out

  • gochujang returned empty text for all four scans and still marked them ok: true; the run log says Failed loading language 'ukr'. It is the most used Actor of the five (40 users a month) and is clean on text PDFs, but it cannot read a Ukrainian scan.
  • nidamindllc is good on scans - the only competitor that kept the invoice table - but it OCRs every PDF, even one with a text layer, which added a typo the file did not have, and it cannot open Word or Excel files at all.
  • lergassy and fabrikit read every format but not the tables. On the invoice lergassy changed a price (96,50 to 96,60), and on the spreadsheet it changed 1,234.50 to 1234.5; fabrikit read the same price as 96,0 on the clean invoice. In an invoice or a price list that is the worst kind of error: it looks right.
  • Mine got all seven files right, including both invoices without lines, with the numbers exactly as written.

About the test

  • One file of each kind, small and synthetic. Real archives have worse scans, stamps and handwriting - try ten of your own files before you choose. That costs a few cents.
  • Every Actor ran with the build that was public on 15 November 2026 (mine: 0.1.20).

While preparing this article, the test results showed me where my Actor could become the best in its category - noisy scans and invoices without table lines - so I improved it right away, before publishing. The latest runs described above confirm it.

Try it

From Python:

from apify_client import ApifyClient

client = ApifyClient("<YOUR_APIFY_TOKEN>")
run = client.actor("ai_admin/document-to-markdown").call(run_input={
    "sources": [{"url": "https://api.apify.com/v2/key-value-stores/FloomuI2DrQCJazY8/records/scan-noisy-borderless-uk.pdf"}],
    "ocrLanguages": ["ukr"],
})
for item in client.dataset(run["defaultDatasetId"]).iterate_items():
    print(item["markdown"])
    print(item["tables"])
